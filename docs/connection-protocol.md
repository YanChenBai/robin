# Robin 连接协议 v2

电脑负责采集与发送，手机负责播放与自动重连。任一端可由用户发起连接，但自动重连只由手机发起，避免双方同时握手。

## 身份与会话

mDNS TXT `protocol=2` 仅用于发现。身份以 Noise XX 握手认证的公钥指纹为准，不以 IP、设备名称或发现 ID 作为授权依据。完整握手哈希作为 `sessionId`；每次 TCP 重连都会产生新的会话标识和音频密钥，旧会话消息不能终止新会话。

电脑的 `_robin-desktop._tcp.` 服务同时广播 `fingerprint`，其值与 Noise 公钥指纹一致。手机原生服务在接收开启期间发现并逐个解析电脑服务，按指纹选择已授权且开启自动连接的记录。发现地址优先，保存地址保留为备用；服务消失后删除候选地址。发现信息不构成授权：握手指纹必须匹配记录，成功接受会话后才持久化新地址。旧桌面未广播指纹时仍可按保存地址连接，无需改变 v2 控制消息。

控制通道使用带长度前缀的 Noise 加密 JSON；音频使用独立 UDP 加密传输。双方升级到 v2 后才能互连，旧版不能静默回退。

## 连接流程

| 顺序 | 发送方      | 消息                      | 含义                                           |
| ---- | ----------- | ------------------------- | ---------------------------------------------- |
| 1    | 双方        | Noise XX 握手             | 认证身份并建立控制加密                         |
| 2    | 电脑        | `hello`                   | 电脑名称、协议版本、控制端口                   |
| 3    | 手机        | `request { intent }`      | `manual` 为显式连接；`resume` 为自动恢复       |
| 4    | 电脑        | `ready` 或 `stop`         | 在手机授权和分配音频端口前检查断开屏障         |
| 5    | 手机        | `pending { code }`        | 首次连接等待核对；已授权身份可直接继续         |
| 6    | 手机        | `accept` 或 `reject`      | 提供新音频密钥、UDP 端口和有效播放缓冲，或拒绝 |
| 7    | 电脑 / 手机 | UDP 音频、`ping` / `pong` | 发送音频并同步 RTT、采集周期、播放缓冲         |

授权记录和自动连接偏好独立。关闭自动连接保留身份授权；手动重新连接仍可使用已授权身份。电脑主动连接手机时，手机回复的意图为 `manual`。

## 主动断开与异常掉线

| 事件                         | 双端处理                                                                                           | 自动重连                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 任一端点击断开               | `stop { sessionId, reason: userDisconnect }`，对端更新策略后回复 `stopped { sessionId }`，释放会话 | 手机停用该电脑的自动重连；电脑持久化该手机指纹的断开屏障 |
| 用户再次点击连接             | 发送 `manual`，解除电脑屏障；保留身份授权                                                          | 不擅自重新开启手机的自动连接设置                         |
| 网络丢失、心跳超时、音频超时 | 清理当前会话和旧音频；保留身份和重连偏好                                                           | 手机按退避策略重试，发送 `resume`                        |
| 关闭接收或退出电脑           | `stop { reason: receiverClosed }`，对端回复确认                                                    | 保留自动连接偏好；接收服务关闭期间不重试                 |
| 断开消息丢失                 | 电脑本地屏障仍然有效；下一次 `resume` 在 `ready` 前再次收到 `userDisconnect`                       | 手机收到后停用重连                                       |
| 两端同时断开                 | 各自应用本地策略，再确认对端当前会话的 `stop`                                                      | 不依赖确认成功才停用重连                                 |

电脑屏障保存于 `%LOCALAPPDATA%/Robin/disconnected.json`，手机授权与偏好保存于应用私有目录的 `connections.json`。存储失败显示错误；当前进程内策略仍立即生效。电脑旧会话拥有独立的状态快照与停止标记，不能覆盖新会话。

## 超时与资源归属

TCP 连接最多 3 秒；Noise 握手读写最多 5 秒；首次配对等待 30 秒。电脑每约 500 ms 发起心跳，读取回复最多 2 秒；手机控制读取和无音频超时均为 3 秒。断开确认必须匹配当前会话 ID，并容忍一个在途心跳；超时也应释放资源，不能恢复用户已取消的连接。一次关闭确认周期可能包含在途心跳及下一次读取，不保证即时完成。

手机回调只读无锁 PCM 环形队列，不能处理控制消息、磁盘 I/O 或持有互斥锁。控制、接收、硬件播放各自拥有线程；关闭时停止 UDP 供给、结束控制线程并清理播放状态。暂停只停止播放消费，保留控制会话，恢复后播放新音频。

## 后台播放

前台使用用户的缓冲设置。进入后台或息屏后，有效缓冲下限暂时提高到 `max(用户下限, 50 ms)`，并按欠载/迟到自适应调整，最高 100 ms；返回前台恢复用户下限与原自适应开关。该策略增加后台延迟，换取对网络批量唤醒的容忍；不改写用户保存的设置。

前台服务持有 CPU 唤醒锁。Android 10–13 同时持有低延迟与高性能 Wi-Fi 锁；Android 14 起高性能锁会退化为低延迟锁，不承诺后台禁用 Wi-Fi 省电。媒体通知和 MediaSession 的封面从 App 图标读取，使用同一资源。

## 验证

本地测试覆盖加密握手、手动连接、缓冲调整、暂停、身份变更、断开确认、主动断开后的无重试、异常掉线的 `resume`、发现新地址后的自动恢复、伪造发现指纹与握手不符时的拒绝、握手阶段阻止旧重连，以及后台缓冲恢复。Android 构建验证 JNI 和 Java 服务的配套变更。

还需真机比较前台、切后台、息屏至少一分钟的欠载与迟到计数；分别验证两端主动断开、断网恢复、电脑 IP 变化后的 NSD 重新发现、重新打开接收、通知封面和通知播放操作。自动化通过不能证明特定手机、Wi-Fi 或蓝牙输出的后台卡顿已消失。
